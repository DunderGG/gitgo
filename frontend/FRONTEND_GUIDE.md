# GitGo Frontend Guide (Beginner Friendly)

This guide explains what is inside the frontend folder and what each file does.

You do not need prior TypeScript knowledge to use this app. Think of TypeScript as JavaScript with extra type checks that help catch mistakes early.

## What this folder is for

The frontend folder contains the desktop app UI:

- React renders the screens and components.
- Zustand stores shared app state in memory.
- Tailwind provides utility CSS classes.
- Vite builds and serves the frontend during development.
- Wails generated bindings let the frontend call Go backend methods.

## Quick mental model

On startup:

1. index.html creates a root element.
2. src/main.tsx mounts React into that root.
3. src/App.tsx chooses what to show based on store state.
4. Components call backend methods through wailsjs bindings.
5. The Zustand store updates, and React re-renders the UI.

## Top-level files and folders

### index.html

Browser shell page. It contains the root element and loads src/main.tsx.

### package.json

Frontend package metadata, scripts, and dependencies.

Main scripts:

- dev: starts Vite dev server
- build: type-checks and builds production assets
- preview: serves built assets locally

### tsconfig.json

TypeScript rules for application code in src.

### tsconfig.node.json

TypeScript rules for tool config files such as vite.config.ts and tailwind.config.ts.

### vite.config.ts

Vite configuration. Enables the React plugin.

### tailwind.config.ts

Tailwind configuration. Tells Tailwind which files to scan for class names.

### postcss.config.js

PostCSS pipeline config for Tailwind and Autoprefixer.

### src/

All application UI code.

### wailsjs/

Generated bindings used to call Go from TypeScript.

Important: these files are generated by Wails and should not be edited manually.

### dist/

Build output created by Vite for production packaging.

### node_modules/

Installed npm dependencies.

## Source code files in src

### src/main.tsx

Entry point for React. Loads global CSS and renders App.

### src/index.css

Global stylesheet. Right now it only imports Tailwind base layers.

### src/App.tsx

Top-level layout and routing-by-state:

- Header with app title and currently opened repo path
- Main panel shows RepoSelector when no repo is open
- Main panel shows CommitList when a repo is open
- StatusBar always visible at bottom

### src/store/repoStore.ts

Global state store using Zustand.

State currently includes:

- repoInfo: opened repository details
- commits: commit list shown in CommitList
- selectedHash: currently selected commit row
- status: normal status text
- error: current error text

Actions currently include:

- setRepo: save repo info and commit list
- selectCommit: set selected row
- setStatus: set status message
- setError: set error message
- clearRepo: reset store to initial state

### src/components/RepoSelector.tsx

Open-repository screen.

It calls generated Wails functions to:

- open native folder picker
- open selected repository in backend
- fetch commit log
- write results into the Zustand store

### src/components/CommitList.tsx

Shows commit history table and legend.

Current behavior:

- renders one row per commit
- unpushed commits use an indigo dot
- pushed commits use a gray dot and reduced opacity
- rows are selectable and highlight when selected

### src/components/StatusBar.tsx

Bottom status area.

Shows:

- branch name
- no-remote or no-upstream warnings
- status message or error message

## Wails binding files you will see

### wailsjs/go/app/App.d.ts

Type declarations for Go methods callable from TypeScript.

Methods currently exposed include:

- SelectDirectory
- OpenRepository
- GetCommitLog
- GetCommitDetail
- RefreshLog
- UpdateCommit

### wailsjs/go/app/App.js

Runtime JavaScript wrappers for those backend calls.

### wailsjs/go/models.ts

Type models generated from Go structs.

## How data flows today

1. User clicks Open Repository in RepoSelector.
2. RepoSelector calls backend through wailsjs functions.
3. Backend returns RepoInfo and commit list.
4. repoStore saves that data.
5. App switches from RepoSelector to CommitList.
6. User selects a row in CommitList and selectedHash updates in repoStore.
7. StatusBar reflects status or error messages from repoStore.

## If you are new to TypeScript, focus on this first

Read in this order:

1. src/main.tsx
2. src/App.tsx
3. src/store/repoStore.ts
4. src/components/RepoSelector.tsx
5. src/components/CommitList.tsx
6. src/components/StatusBar.tsx

That path will give you the big picture before diving into config files.
